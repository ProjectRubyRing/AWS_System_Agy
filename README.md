## 2. シート構成と役割分担

大量のシステムやAWSサービスを含める場合でも破綻せず、読み手や目的に応じて使い分けられるよう、**「概要」と「詳細」、およびそれぞれの「パーツ集」を明確にシート分割**しています。

```
AWS_現場システム統合構成図_テンプレート.xlsx
 ├─ 00_利用ガイド・凡例規約   … 全体ルール、モノトーン色彩定義、作図のコツ（Altスナップ等）
 ├─ 01_構成図_概要           … 【概要用】経営層・PM向け 全体鳥瞰図（現場〜中継〜AWS〜外部連携）
 ├─ 02_構成図_詳細           … 【詳細用】インフラ・NW設計者向け Multi-AZ / サブネット精密図
 ├─ 03_パーツ集_概要用       … 概要図向けマクロ境界枠、階層カード、大口径接続線、概要凡例
 └─ 04_パーツ集_詳細用       … 詳細図向け全AWSアイコン(40+)、現場機器(20+)、線種、ポートタグ、表
```

### 各シートの詳細仕様

#### ① `00_利用ガイド・凡例規約`
- **対象読者**: 構成図の作成者・レビュー担当者
- **内容**:
  - 本テンプレートの設計思想とシートごとの使い分け基準
  - モノトーンカラーパレットのカラーコード（Hex/RGB）と適用ルール
  - Excelで図形がズレない「セル方眼（方眼紙グリッド）」と `Alt` キードラッグ吸着テクニック
  - 印刷時（A3横 / A4横 横1ページ収まり）の設定ガイド
  - 通信線種（実線・破線・二重線・点線・双方向）の定義標準

#### ② `01_構成図_概要`（概要用テンプレートシート）
- **対象読者**: 経営層、ステークホルダー、PM、業務部門、全体関係者
- **設計コンセプト**: 1枚でシステム全体のデータ流通と結合関係が直感的に把握できるマクロ図
- **レイアウト構造**:
  - **上部**: メタ情報ヘッダー（システム名、バージョン、作成日、機密区分、承認印欄）
  - **左側【現場・拠点領域】**: 製造工場（OT系設備）、エッジGW、拠点オフィス（IT系端末）
  - **中央【ネットワーク中継層】**: AWS Direct Connect 専用線（主系）、Site-to-Site VPN（副系）、モバイル回線
  - **右側【AWS クラウド領域】**: 東京リージョン（取込層 → 処理層 → 永続化層 → 外部配信層）
  - **下部【横断共通基盤】**: 統合セキュリティ（WAF/KMS/IAM）、運用監視（CloudWatch/GuardDuty）
  - **最下部【概要仕様表】**: 8大サブシステムの役割、採用技術、SLA・冗長化方針一覧表

#### ③ `02_構成図_詳細`（詳細用テンプレートシート）
- **対象読者**: クラウドインフラエンジニア、NW技術者、セキュリティ担当、DevOps、開発者
- **設計コンセプト**: 実装・構築・設定・監査に必要なパラメータをすべて網羅した精密図
- **レイアウト構造**:
  - **オンプレミス詳細**:
    - OT系 隔離制御ネットワーク（`192.168.10.0/24`）: PLC、センサー、産業ロボット、Modbus TCP (Port 502)
    - IT系 現場業務ネットワーク（`192.168.20.0/24`）: 産業用エッジPC (Greengrass)、現場HMI、Wi-Fi
    - 現場 DMZ 境界セキュリティ（`192.168.0.0/24`）: 次世代UTM/FW、拠点Customer GWルータ
  - **ネットワーク相互接続層**: Direct Connect（VLAN 100）、Transit Gateway（ASN 64512）、IPsec VPN
  - **AWS Multi-AZ VPC（`10.0.0.0/16`）**:
    - Availability Zone 1a (`ap-northeast-1a`) & 1c (`ap-northeast-1c`) の対称冗長構成
    - Public Subnets (`10.0.1.0/24`, `10.0.2.0/24`): IGW, NAT Gateway, Internet-Facing ALB
    - Private App Subnets (`10.0.11.0/24`, `10.0.12.0/24`): ECS Fargate Cluster, EC2 Auto Scaling
    - Private DB Subnets (`10.0.21.0/24`, `10.0.22.0/24`): Amazon Aurora PostgreSQL Multi-AZ
    - マネージド・サーバーレス層: S3 Data Lake, IoT Core, Kinesis, DynamoDB, Lambda
    - セキュリティグループ境界・プロトコル・ポート明記
  - **最下部【詳細リソース設計一覧表】**: No.01〜15の全リソース種別、CIDR/IP、ポート、SG、冗長化方式、設計仕様一覧

#### ④ `03_パーツ集_概要用`（概要専用パーツカタログ）
- **概要用マクロ境界コンテナ枠**: 現場・工場領域枠、通信キャリア専用線枠、AWS Cloud全体枠
- **概要用主要機能階層カード**: 取込層、処理層、蓄積層、統制層、外部連携層
- **概要用代表アイコン**: Direct Connect、Transit Gateway、IoT Core、ECS、Lambda、S3、Aurora 等
- **大口径接続線・データフロー線**: 専用線太線、同期実線矢印、非同期破線矢印、双方向矢印
- **エグゼクティブ凡例ブロック**: 構成図の右下等にそのまま貼れる凡例カード

#### ⑤ `04_パーツ集_詳細用`（詳細専用パーツカタログ）
- **詳細ネットワーク境界枠**: VPC枠、Public Subnet枠、Private App Subnet枠、Isolated DB Subnet枠
- **全AWSサービス詳細アイコン（40+種）**:
  - Compute & Container: EC2, ECS, EKS, Lambda, Fargate, Batch
  - Storage & Delivery: S3, Glacier, EFS, EBS, CloudFront
  - Database & Search: RDS, DynamoDB, ElastiCache, OpenSearch, DocumentDB
  - Networking: VPC, ALB, NLB, Route 53, Transit Gateway, Direct Connect, DX Gateway, Site VPN, NAT Gateway, Internet Gateway, API Gateway, PrivateLink
  - IoT & Streaming: IoT Core, Greengrass, SiteWise, Kinesis, SQS, SNS, EventBridge, Step Functions
  - Security & Governance: IAM, KMS, Secrets Manager, WAF, GuardDuty, CloudWatch, CloudTrail, SSM
- **全現場・OT・IT機器アイコン（20+種）**:
  - 拠点・施設: Factory, Office, Local DC, Warehouse, Store
  - 産業制御(OT): PLC, Sensor, Robot, Machine Tool, HMI, CCTV Camera
  - 現場IT・エッジ: Edge IPC, IoT Gateway, Local Server, Local NAS, Edge Router, UTM/FW, L3 Switch, Wi-Fi AP
  - 現場端末: Tablet, Handy Terminal, Client PC, 5G/LTE Cellular, Direct Link, Closed VPN
- **通信プロトコル・ポートタグ（14種）**:
  - `HTTPS:443`, `MQTT:8883`, `Modbus:502`, `PostgreSQL:5432`, `MySQL:3306`, `SSH:22`, `RDP:3389`, `OPC-UA:4840`, `NTP:123`, `DNS:53`, `Syslog:514`, `REST API`, `DX 1Gbps`, `IPsec VPN`
- **ステータス・ゾーンバッジ（14種）**:
  - `[本番 PROD]`, `[検証 STG]`, `[開発 DEV]`, `[Multi-AZ 冗長]`, `[Active]`, `[Standby]`, `[暗号化 KMS/TLS]`, `[マネージド]`, `[OT系]`, `[IT系]`, `[DMZ]`, `[Public]`, `[Private]`, `[DB]`
- **詳細線種ストリップ（7種）**: 実線、破線、二重線、太破線、点線、双方向、一点鎖線
- **詳細リソース設計一覧表（空テンプレート）**: コピペして即座に表拡張可能

## 3. デザイン仕様・ガイドライン

### ① フォント（Meiryo UI 統一）
- Excelで作成されるすべてのセル、表見出し、データ行、図形内テキスト、注記に **`Meiryo UI`** を適用しています。
- **文字サイズ階層**:
  - シートメインタイトル: **13pt Bold**
  - セクション見出し: **10.5pt Bold**
  - ボックスヘッダー / テーブル見出し: **8.5〜9.5pt Bold**
  - データセル / アイコン内テキスト: **8〜8.5pt Regular/Bold**
  - 注記・フッター: **7.5〜8pt Regular**

### ② モノトーンカラーパレット
日本のエンタープライズSI・企業インフラ標準に準拠した、高品位なモノトーン（チャコール〜スレートグレー〜ライトグレー）配色を採用しています。
カラー印刷はもちろん、**白黒コピー・白黒印刷時でもコントラストが落ちず、完璧な視認性**を維持します。

| 用途 | カラーコード | 外観 |
| :--- | :--- | :--- |
| **最重要見出し・タイトル外枠** | `#1A202C` | 極暗濃灰（Charcoal Dark） |
| **アイコンヘッダー・大見出し** | `#2D3748` | 濃スレート（Deep Slate） |
| **サブネット境界・二重線** | `#4A5568` | 中間スレート（Medium Slate） |
| **区切り線・非同期線・注記** | `#718096` | ニュートラルグレー（Neutral Gray） |
| **DBサブネット・表ゼブラ** | `#E2E8F0` | 薄灰塗りつぶし（Soft Gray） |
| **VPC背景・入力枠** | `#EDF2F7` | 極薄スレート（Light Slate） |
| **AWS Cloud全体背景・現場外枠** | `#F7FAFC` | オフホワイト（Off-White） |
| **個別カード・アイコン下地** | `#FFFFFF` | 純白（Pure White） |

### ③ セル方眼（マイクログリッド）と配置テクニック
- ワークシートは **横幅 3.4 / 行の高さ 18pt** の均一な「セル方眼紙」構造になっています。
- **Excel操作のコツ**:
  > **[Alt] キーを押しながらドラッグ＆ドロップ**
  > アイコン画像や図形枠を移動・リサイズする際、`Alt` キーを押したまま操作すると、自動的にセルの境界線にピタッと吸着（スナップ）します。これにより、目視の手動調整で起こりがちな「1ピクセルのズレ」「線の不揃い」が完全に解消されます。

## 4. 大規模システム・多サービス記述時のベストプラクティス

現場の設備機器が数百台に及ぶ場合や、AWSサービスが多岐にわたる場合でも、以下の構成パターンを用いることで常に美しい可読性を保てます。

1. **概要図（`01_構成図_概要`）での集約表現**:
   - 個別のEC2やPLCを1台ずつ描くのではなく、「製造ラインA設備群」「エッジGW群」「マイクロサービスコンテナ層」のようにドメイン単位でマクロ集約して記載します。
2. **詳細図（`02_構成図_詳細`）のシート複製分割**:
   - システム規模に応じて、`02_構成図_詳細` シートを右クリックして「移動またはコピー」し、以下の例のようにサブシステム単位で分割・詳細化します。
     - `02_詳細_工場OT・データ収集系`
     - `02_詳細_基幹AP・DB連携系`
     - `02_詳細_外部配信・BI分析系`
3. **スペック表との双方向対応**:
   - 図中にはリソースの識別ID（例: `PLC-01`, `alb-external`, `aurora-db`）をバッジとして配置し、詳細なスペック・IP・ポート・冗長化方式は図面直下の「詳細設計リソーススペック一覧表」に記載することで、図面が文字で埋もれるのを防ぎます。

## 5. 再生成・カスタマイズ方法

本テンプレートはPythonスクリプトによって完全に自動生成されているため、必要に応じてプログラムから一括更新・再構築が可能です。

```powershell
# Python UTF-8モードで生成スクリプトを実行
python -X utf8 build_excel_template.py
```

実行が完了すると、最新の `AWS_現場システム統合構成図_テンプレート.xlsx` が生成されます。
